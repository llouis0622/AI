# 7부 퀴즈. 거대 언어 모델

범위: [21장](/book/21-llm-pretraining) ~ [24장](/book/24-agents)

<QuizProgress prefix="p7" :total="14" />

<Quiz id="p7-01" q="'다음 토큰 예측'이라는 목표가 광범위한 능력을 낳는 이유는?">

**답:** 수조 개의 빈칸을 낮은 손실로 채우는 유일한 길은 문장을 만든 세계의 구조(사실·논리·코드 규칙·심리)를 파라미터에 압축하는 것뿐이다. 목표의 외양은 시시하지만 그것을 잘하려면 세계의 모형이 필요하다. → [21장](/book/21-llm-pretraining)

</Quiz>

<Quiz id="p7-02" q="스케일링 법칙이 말하는 바와, 모델·데이터 배분에 관한 두 번째 발견은?">

**답:** 파라미터·데이터·계산을 늘리면 손실이 거듭제곱 법칙으로 예측 가능하게 감소한다. 주어진 예산에서 모델과 데이터는 함께 키워야 최적(파라미터당 토큰 약 20개) — 한때의 거대 모델들은 데이터에 비해 지나치게 컸다. → [21장](/book/21-llm-pretraining)

</Quiz>

<Quiz id="p7-03" q="환각이 '거짓말'이 아닌 이유와, 대응되는 처방 셋은?">

**답:** 모델은 참인 문장이 아니라 그럴듯한 다음 토큰을 배웠고, 참/거짓 검증 장치가 목표에 없었다. 처방: 근거 문서 제공(RAG), '모른다'고 말하도록 정렬, 출력의 외부 검증(도구·에이전트). → [21장](/book/21-llm-pretraining)

</Quiz>

<Quiz id="p7-04" q="'단계별로 생각하라'가 성능을 올리는 구조적 이유는?">

**답:** 한 토큰 = 한 번의 순전파라는 제약 안에서, 중간 단계를 토큰으로 써 내려가는 것이 모델에게 계산 자원을 늘려 주는 유일한 길이다. 최신 모델이 '생각하는 토큰'을 길게 생성하도록 훈련되는 이유. → [21장](/book/21-llm-pretraining)

</Quiz>

<Quiz id="p7-05" q="사전학습 모델이 질문에 질문으로 답하는 현상과 정렬의 목표를 설명하라.">

**답:** 사전학습 모델은 문서를 이어 쓰는 기계라, 문제집을 봤다면 다음 문제를 이어 낸다. 정렬은 이를 도움이 되고·정직하고·무해한 조수로 — '할 수 있는 것'에서 '하려 하는 것'으로 — 바꾸는 절차다. → [22장](/book/22-alignment)

</Quiz>

<Quiz id="p7-06" q="SFT의 원리와 한계는?">

**답:** (지시, 이상적 답변) 쌍으로 미세조정해 대화의 형식·태도를 가르친다. 능력은 이미 있어 소량으로 충분. 한계: '더 낫다'는 정도의 판단은 이상적 답변 하나로 담을 수 없어 비교를 가르쳐야 한다. → [22장](/book/22-alignment)

</Quiz>

<Quiz id="p7-07" q="RLHF의 세 단계와 KL 벌점이 필요한 이유는?">

**답:** SFT → 보상 모델(사람의 비교 판단을 학습한 자동 채점기) → 강화학습(PPO)으로 채점기 점수를 높이는 방향으로 정책 갱신. 채점기는 근사일 뿐이라 허점을 파고드는 채점기 해킹이 생기므로, 원래 모델에서 멀어지면 KL 벌점을 준다. → [22장](/book/22-alignment)

</Quiz>

<Quiz id="p7-08" q="DPO가 RLHF를 어떻게 압축했는가?">

**답:** 보상 모델을 거치는 강화학습의 최적해를 대수적으로 정리하면, 선호 쌍 데이터로 정책을 직접 학습하는 분류형 손실 하나가 된다 — 선호 답변 확률↑ 비선호↓, 참조 모델에서 너무 멀어지지 않게. 보상 모델도 RL 루프도 없다. → [22장](/book/22-alignment)

</Quiz>

<Quiz id="p7-09" q="LLM 활용의 세 다이얼과 시도 순서, 그리고 그 순서인 이유는?">

**답:** 프롬프트(입력) → RAG(입력에 정보 추가) → 파인튜닝(모델 변경). 비용과 난이도가 이 순서로 오르므로 왼쪽부터 시도한다. → [23장](/book/23-using-llms)

</Quiz>

<Quiz id="p7-10" q="RAG의 두 단계와, RAG 실패의 대부분이 어디에 있는가?">

**답:** 질문과 관련된 문서 조각을 의미 검색으로 찾아(검색), 근거로 프롬프트에 넣어 답하게 한다(생성). 실패의 대부분은 검색 — 관련 조각을 못 찾으면 어떤 모델도 답할 수 없다. 검색 품질(정답 조각이 상위 k 안에 든 비율)을 따로 측정하라. → [23장](/book/23-using-llms)

</Quiz>

<Quiz id="p7-11" q="'사내 규정집으로 파인튜닝했더니 틀린 조항을 댄다'의 원인과 처방은?">

**답:** 파인튜닝은 행동·형식의 체화이지 지식 주입이 아니다(사실은 사전학습에서 수백 번 노출되어야 저장된다). 지식은 RAG로 넣어 주고, 파인튜닝은 문체·형식에 쓴다. → [23장](/book/23-using-llms)

</Quiz>

<Quiz id="p7-12" q="도구 사용의 원리 세 조각과, 그것이 LLM 한계에 대한 처방인 이유는?">

**답:** ① 도구 명세를 알려 주고, ② 모델이 구조화된 호출을 출력하면, ③ 우리 코드가 실행해 결과를 돌려준다. 지식 마감일→검색, 산수 취약→계산기, 환각→DB 조회처럼 약점을 정확한 외부 시스템에 위임한다. → [24장](/book/24-agents)

</Quiz>

<Quiz id="p7-13" q="에이전트의 실체를 한 문장으로 말하고, 도구 실패를 예외로 중단하지 않는 이유를 설명하라.">

**답:** 도구 사용의 반복문 — 관찰·생각·행동·관찰 루프. 실패를 오류 메시지로 돌려주면 모델이 읽고 스스로 복구한다 — 이 자기 복구가 스크립트와 에이전트의 결정적 차이다. → [24장](/book/24-agents)

</Quiz>

<Quiz id="p7-14" q="에이전트 안전장치 다섯 가지를 나열하라.">

**답:** 최소 권한(필요한 도구만, 읽기/쓰기 분리), 샌드박스(폴더·격리 실행·허용 목록), 되돌리기 어려운 행동의 사람 승인, 반복·비용·시간 상한과 로그, 도구 결과를 지시가 아닌 데이터로 취급(프롬프트 주입 방어). 브레이크 없는 차가 빠른 차가 아니다. → [24장](/book/24-agents)

</Quiz>
