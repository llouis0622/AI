# 9부 퀴즈. 현장

범위: [27장](/book/27-to-production) ~ [28장](/book/28-keep-learning)

<QuizProgress prefix="p9" :total="8" />

<Quiz id="p9-01" q="학습-서빙 왜곡이란 무엇이며, 구조적으로 막는 방법은?">

**답:** 학습 시와 서빙 시의 전처리(정규화 상수 등)가 달라 성능이 소리 없이 깎이는 것. 전처리 코드를 학습·서빙이 같은 함수로 공유한다. → [27장](/book/27-to-production)

</Quiz>

<Quiz id="p9-02" q="동적 배칭이 처리량을 올리는 원리와 대가는?">

**답:** GPU는 수천 건을 동시에 처리할 때 효율이 나므로, 수 밀리초 동안 도착한 요청을 모아 한 배치로 추론한다. 대가는 그 대기 시간 — 지연과 처리량의 트레이드오프 다이얼. → [27장](/book/27-to-production)

</Quiz>

<Quiz id="p9-03" q="LLM 서빙에서 KV 캐시가 필수인 이유와 메모리를 지배하는 이유는?">

**답:** 생성은 토큰 하나씩 직렬이고 매 토큰마다 과거 전체에 어텐션하므로, 이전 토큰의 키·밸류를 저장해 재계산을 피한다. 크기가 (층×헤드×길이×배치)에 비례해 긴 문맥·큰 배치에서 가중치보다 커진다. → [27장](/book/27-to-production)

</Quiz>

<Quiz id="p9-04" q="평균 지연이 아니라 p95/p99를 봐야 하는 이유는?">

**답:** 평균 50ms여도 p99가 2초면 100명 중 1명은 2초를 기다린다 — 사용자 경험은 꼬리가 결정한다. 요구사항을 숫자로 적고 부하 테스트로 재기 전에는 믿지 않는다. → [27장](/book/27-to-production)

</Quiz>

<Quiz id="p9-05" q="데이터 드리프트와 컨셉 드리프트의 차이와 각각의 감지 방법은?">

**답:** 데이터 드리프트는 입력 분포 $p(x)$의 변화 — 입력 통계 모니터링으로 정답 없이 감지. 컨셉 드리프트는 $p(y|x)$의 변화 — 지연 레이블이 도착해야 성능 하락으로 감지. → [27장](/book/27-to-production)

</Quiz>

<Quiz id="p9-06" q="섀도·카나리·A/B 배포를 위험과 정보의 관점에서 비교하라.">

**답:** 섀도는 응답을 쓰지 않아 위험 0, 실제 분포에서의 동작 정보. 카나리는 소수 트래픽에 노출해 작은 위험, 실제 지표 정보. A/B는 무작위 분할로 비즈니스 지표의 통계적 비교 — '모델 지표가 좋다'와 '사업에 좋다'는 다르다. 언제나 롤백 가능하게. → [27장](/book/27-to-production)

</Quiz>

<Quiz id="p9-07" q="이 분야에서 '변하지 않는 것'을 다섯 가지 이상 들어라.">

**답:** 학습은 손실 최소화, 일반화가 진짜 목표, 데이터가 모델을 만든다, 평가 없는 성적은 소문, 표현이 바뀌면 도구가 이식된다, 귀납 편향과 데이터 양은 교환 관계, 곱의 사슬은 소실하고 지름길이 살린다. 새 논문의 대부분은 이들의 새 조합이다. → [28장](/book/28-keep-learning)

</Quiz>

<Quiz id="p9-08" q="새 모델 발표를 '이해했다'고 말하려면 답해야 할 다섯 질문은?">

**답:** 입력 표현은? 아키텍처는 Transformer의 어떤 변주인가? 학습 목표와 데이터는? 정렬은 어떻게? 평가는 무엇으로? 이 다섯에 답이 나오면 이해한 것이고, 안 나오면 아직 발표 자료일 뿐이다. → [28장](/book/28-keep-learning)

</Quiz>
