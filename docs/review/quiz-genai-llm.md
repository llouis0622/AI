# 퀴즈 04. 생성 모델과 LLM

범위: [Lecture 11~15](/curriculum/ch05/lecture11), [핸드북 Part 09 · Generative Models](/handbook/09-generative-models/).

<QuizProgress prefix="gen" :total="12" />

<Quiz id="gen-01" q="판별 모델과 생성 모델의 차이를 확률 관점에서 설명하라.">

**답:** 판별 모델은 조건부 분포 $p(y|x)$ — 입력이 주어졌을 때 레이블의 확률 — 만 모델링한다. 생성 모델은 데이터 자체의 분포 $p(x)$(또는 결합분포 $p(x,y)$)를 모델링해 새로운 샘플을 만들어낼 수 있다. 생성은 "데이터 분포를 배워 그 분포에서 샘플링하는 문제"다. → [Lecture 11](/curriculum/ch05/lecture11)

</Quiz>

<Quiz id="gen-02" q="VAE의 ELBO는 어떤 두 항으로 이루어지며 각각 무슨 역할을 하는가?">

**답:** ELBO = 재구성 항 $\mathbb{E}_{q(z|x)}[\log p(x|z)]$ − KL 항 $D_{KL}(q(z|x)\,\|\,p(z))$. 재구성 항은 잠재변수에서 입력을 잘 복원하도록, KL 항은 인코더의 사후분포가 사전분포(표준정규)에서 멀어지지 않도록 정규화한다. 로그가능도를 직접 최대화할 수 없어 그 하한(ELBO)을 최대화하며, 재파라미터화 트릭으로 샘플링을 미분 가능하게 만든다. → [핸드북 Part 09 · 02편](/handbook/09-generative-models/02-vae)

</Quiz>

<Quiz id="gen-03" q="GAN의 학습 구조와 대표적 실패 모드인 모드 붕괴를 설명하라.">

**답:** 생성자는 판별자를 속이는 샘플을, 판별자는 진짜/가짜를 구분하도록 미니맥스 게임으로 동시 학습한다. 모드 붕괴는 생성자가 데이터 분포의 일부 모드만 생성해도 판별자를 속일 수 있어 다양성이 무너지는 현상으로, WGAN(Wasserstein 거리 + 립시츠 제약) 등이 학습 신호를 안정화해 완화한다. → [핸드북 Part 09 · 03~04편](/handbook/09-generative-models/03-gan-fundamentals)

</Quiz>

<Quiz id="gen-04" q="확산 모델의 순방향 과정과 역방향 과정은 각각 무엇을 하는가?">

**답:** 순방향 과정은 데이터에 가우시안 노이즈를 점진적으로 더해 순수 노이즈로 만드는 고정된 마르코프 과정이다. 역방향 과정은 그 반대 — 노이즈에서 시작해 각 단계의 노이즈를 예측·제거하며 데이터를 복원하는 과정을 신경망으로 학습한다. DDPM의 학습 목표는 각 시점에서 추가된 노이즈 $\epsilon$을 예측하는 회귀 문제로 단순화된다. → [핸드북 Part 09 · 06~07편](/handbook/09-generative-models/06-diffusion-forward-process)

</Quiz>

<Quiz id="gen-05" q="Latent Diffusion(Stable Diffusion)이 픽셀 공간 확산보다 효율적인 이유는?">

**답:** 오토인코더로 이미지를 저차원 잠재 공간으로 압축한 뒤 그 공간에서 확산을 수행하기 때문이다. 지각적으로 중요하지 않은 고주파 세부를 오토인코더에 맡기고, 비싼 반복 샘플링은 훨씬 작은 잠재 텐서에서 돌므로 계산량이 크게 준다. 텍스트 조건은 크로스 어텐션으로 주입하고, CFG(classifier-free guidance)로 조건 충실도를 조절한다. → [핸드북 Part 09 · 09편](/handbook/09-generative-models/09-latent-diffusion-and-guidance)

</Quiz>

<Quiz id="gen-06" q="LLM의 사전학습 목표는 무엇이며, 그 단순한 목표가 왜 광범위한 능력으로 이어지는가?">

**답:** 다음 토큰 예측(인과 언어 모델링) — 이전 토큰들이 주어졌을 때 다음 토큰의 분포를 맞추는 것이다. 방대한 텍스트의 다음 토큰을 잘 맞추려면 문법, 사실, 추론 패턴, 코드 규칙 등 텍스트를 생성한 세계의 구조를 압축해야 하므로, 단일 목표가 다양한 능력의 학습으로 이어진다. → [Lecture 13](/curriculum/ch06/lecture13)

</Quiz>

<Quiz id="gen-07" q="스케일링 법칙이 말하는 바와 Chinchilla의 핵심 교훈을 요약하라.">

**답:** 손실은 파라미터 수, 데이터량, 컴퓨트를 늘릴수록 거듭제곱 법칙으로 예측 가능하게 감소한다. Chinchilla의 교훈: 주어진 컴퓨트에서 모델 크기와 데이터량을 함께 키워야 최적이며(대략 파라미터당 20토큰), 당시의 대형 모델들은 데이터 대비 과대(undertrained)했다 — 같은 컴퓨트면 더 작은 모델을 더 많은 데이터로 학습하는 편이 낫다. → [Lecture 14](/curriculum/ch06/lecture14), [핸드북 Part 10 · 01편](/handbook/10-llm-engineering/01-scaling-laws)

</Quiz>

<Quiz id="gen-08" q="사전학습된 LLM이 곧바로 유용한 어시스턴트가 아닌 이유와, 정렬 파이프라인의 세 단계를 말하라.">

**답:** 사전학습 모델은 "다음 토큰 예측기"일 뿐 지시를 따르거나 유해 요청을 거절하도록 훈련되지 않았다. 정렬 파이프라인: (1) SFT — 지시-응답 데이터로 지도 미세조정, (2) 보상 모델 학습 — 사람 선호 비교 데이터로 응답 품질 채점기 학습, (3) RLHF — 보상을 최대화하도록 PPO 등으로 정책 최적화(또는 DPO로 보상 모델 없이 선호를 직접 최적화). → [Lecture 15](/curriculum/ch06/lecture15)

</Quiz>

<Quiz id="gen-09" q="DPO가 RLHF(PPO) 대비 갖는 실용적 장점은 무엇인가?">

**답:** DPO는 선호 쌍 데이터로부터 최적 정책의 닫힌 형태를 유도해, 별도의 보상 모델 학습과 온라인 RL 루프 없이 단순한 분류형 손실로 선호를 직접 최적화한다. 구현이 간단하고 안정적이며 메모리·컴퓨트가 적게 든다(참조 모델과 정책 모델만 필요). → [핸드북 Part 10 · 09편](/handbook/10-llm-engineering/09-dpo)

</Quiz>

<Quiz id="gen-10" q="인컨텍스트 학습(in-context learning)이란 무엇이며 파인튜닝과 어떻게 다른가?">

**답:** 프롬프트에 예시 몇 개를 넣어 주면 가중치 갱신 없이 그 패턴을 따라 새 입력을 처리하는 능력이다. 파인튜닝은 그래디언트로 가중치를 실제로 바꾸지만, 인컨텍스트 학습은 순전파만으로 컨텍스트의 정보를 활용한다 — 스케일이 커지며 창발적으로 강해진 대표적 능력이다. → [Lecture 14](/curriculum/ch06/lecture14)

</Quiz>

<Quiz id="gen-11" q="환각(hallucination)은 왜 생기는가? 다음 토큰 예측 목표와 연결해 설명하라.">

**답:** 모델은 "그럴듯한 다음 토큰"을 생성하도록 훈련될 뿐, 사실 여부를 검증하는 메커니즘이 없다. 훈련 분포에서 유창하고 자신감 있는 텍스트가 보상되므로, 지식이 없는 질문에도 형식적으로 그럴듯한 답을 만들어낸다. 완화책: RAG로 근거 문서를 제공, 정렬 단계에서 불확실성 표현 학습, 생성 후 검증. → [Lecture 13](/curriculum/ch06/lecture13), [핸드북 Part 10 · 22편](/handbook/10-llm-engineering/22-llm-evaluation)

</Quiz>

<Quiz id="gen-12" q="FID는 생성 이미지 품질을 어떻게 측정하는가?">

**답:** 진짜 이미지들과 생성 이미지들을 Inception 네트워크의 특징 공간에 통과시켜 각각 가우시안으로 근사한 뒤, 두 분포 간 Fréchet 거리를 계산한다. 낮을수록 생성 분포가 실제 분포에 가깝다는 뜻이며, 품질과 다양성을 함께 반영하지만 특징 추출기와 샘플 수에 민감하다. → [핸드북 Part 09 · 11편](/handbook/09-generative-models/11-generative-evaluation)

</Quiz>
