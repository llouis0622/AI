# Part 14 · Practitioner Guide

## 이 파트의 목표

앞의 열세 파트가 지식이라면 이 파트는 작업 방식이다. 같은 지식을 가진 두 엔지니어의 산출 속도가 몇 배씩 차이 나는 이유는 대개 여기에 있다. 실험을 어떻게 기록하는가, 논문을 어떤 순서로 읽는가, 학습이 실패했을 때 무엇부터 확인하는가, 최적화 대상을 어떻게 고르는가.

이 파트의 내용은 대부분 절차와 체크리스트다. 수식 유도는 적고, 대신 판단 트리와 즉시 붙여 쓸 수 있는 코드가 많다.

## 반복되는 작업 루프

## 문서 구성

01번은 실험 명명 규칙과 기록 항목이다. 사후에 "그때 그 설정이 뭐였지"를 없애는 것이 목표다.

02번은 논문 읽기와 재현 절차다. 초록-그림-결론-방법 순으로 읽는 이유와 재현 시 어디서 막히는지를 다룬다.

03번은 ML 코드 리뷰 체크포인트다. 일반 소프트웨어 리뷰와 다른 지점, 즉 누수, 형상, 정규화 위치, 랜덤성 제어에 집중한다.

04번은 증상별 원인 후보 트리다. 이 아카이브 전체에서 가장 자주 열어보게 될 문서로 설계했다.

05번은 최적화 우선순위 결정 절차다. 측정 없는 최적화를 막는다.

06번은 코드 레시피 모음이다. 시드 고정, AMP 학습 루프, DDP 런처, 체크포인트 저장과 복원, 프로파일링, 혼동행렬 그리기 같은 조각을 복사해 바로 쓸 수 있게 모았다.

## 한 문장 원칙 모음

측정하지 않은 것은 최적화하지 않는다.

기준선을 재현하지 못하면 개선을 주장하지 않는다.

한 번에 하나만 바꾼다.

작은 배치 하나를 과적합시키지 못하는 모델은 큰 데이터에서도 학습되지 않는다.

검증 세트를 여러 번 들여다볼수록 검증 세트는 학습 세트가 된다.

지표가 좋아졌는데 이유를 설명하지 못하면 아직 좋아진 것이 아니다.

배포 경로에 롤백이 없으면 그것은 배포가 아니라 도박이다.
